LAN Multiplayer Budget Challenge

A competitive LAN-based shopping game where participants race against time to make smart purchasing decisions within a configurable budget. The project combines multiplayer data synchronization, dynamic gameplay configuration, persistent results, and a shared leaderboard.

Sole Developer Unity / C# Mirror Networking Client-Provided Art

About the Game

Players browse a virtual store, add products to their cart, and try to achieve a strong shopping result before the countdown ends. Their purchases are evaluated against configurable spending thresholds, and eligible results contribute to a competitive leaderboard shared over the local network.

The game includes configurable item selection, shopping and checkout, animated receipts, performance categories, and synchronized player records.

My Role & Contributions

I was the sole developer responsible for the game's technical implementation, including the networking, gameplay logic, configuration, persistence, user interfaces, and integration. The visual art assets were supplied by the client.

  • Implemented Mirror networking using SyncVars, Commands, and ClientRpc calls.
  • Built configurable shopping gameplay, timed rounds, checkout, and score evaluation.
  • Developed a 24-item selector with validation and synchronized configuration.
  • Implemented persistent player data and configuration using JSON files and PlayerPrefs.
  • Built the result screens, rank calculation, receipt animations, and UI feedback.
  • Integrated the client-provided artwork into the complete Unity experience.

Technical Features

LAN Networking & Sync

Mirror SyncVars and hooks distribute player lists and session configuration. Commands submit new results and configuration changes, while RPCs coordinate actions such as leaderboard resets and scene reloads.

Dynamic Item Configuration

A custom UI allows exactly 24 unique products to be selected from an item database. The selection is validated, serialized, and restored from synchronized or locally stored settings.

Reliable Configuration Loading

The game checks live network configuration, cached PlayerPrefs, and a local JSON file. A short initialization wait and fallback item selection help handle delayed configuration during scene loading.

Budget-Based Gameplay

Players add and remove items from their carts while tracking spending and savings. A configurable countdown drives the session, ending in a receipt and performance-based result.

Persistent Leaderboards

Player results are stored locally and synchronized through Mirror. Rankings use configurable eligibility rules, a session timestamp, spending values, and item-count tie handling.

UI & Presentation

Developed gameplay, configuration, receipt, results, and leaderboard interfaces with Unity UI and TextMeshPro, plus DOTween animations, visual effects, and audio feedback.

Engineering Challenges

Handling late network data

Network configuration can arrive after a Unity scene has initialized. I used synchronization callbacks, cached values, persistent configuration, and a timed initialization wait to avoid starting rounds with missing items.

Keeping game sessions configurable

Rather than hardcoding a single round, I built systems around adjustable budgets, timers, item selections, and scoring thresholds.

Maintaining consistent results

Results are serialized for persistence and submitted to the networked player list. The leaderboard filters results by session and calculates rankings with explicit handling for tied spending and item counts.
