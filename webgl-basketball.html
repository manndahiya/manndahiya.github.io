WebGL Basketball Game

A browser-based basketball game developed in Unity, featuring interactive shooting mechanics and responsive visual feedback. My main challenge was adapting a much larger PC version for WebGL by reducing expensive assets and finding lightweight alternatives to preserve the game's visual experience.

Build Size Optimization

Technical Contributions

Alembic Animation Replacement

The PC version used an Alembic animation for the basketball net. For WebGL, I replaced it with a lightweight transform-scaling animation triggered by ball impact, creating a convincing net reaction without the heavier animation asset.

Texture & Asset Compression

Reduced texture resolutions and applied Unity Crunch compression where appropriate to lower packaged asset sizes while keeping the visuals acceptable.

Particle-Based Visual Effects

Replaced selected background image elements with Unity Particle Systems, allowing visual effects to be recreated without relying on the original image assets.

WebGL Platform Adaptation

Adjusted assets and visual implementations for the browser version, prioritizing a smaller build while retaining gameplay functionality and feedback.

Development Challenges

01. Replacing Heavy Animation Assets

The basketball net was originally animated using Alembic, which was suitable for the PC version but undesirable for the smaller WebGL build.

Instead of keeping the original animation, I used a simpler approach: scaling the net when the ball made contact and returning it to its original state. This maintained the impression of a reactive net using lightweight transform changes.

02. Balancing Visuals & Build Size

Reducing the size of the game required deciding which visual assets could be simplified, compressed, or replaced without affecting the overall experience.

I reduced unnecessary texture resolution, used Crunch compression, and substituted selected background visuals with particle-based effects.

03. Adapting the Game for WebGL

The desktop version and browser version had different asset-size and delivery requirements.

My approach was to review the expensive visual features individually, replace them with simpler solutions where practical, and reduce packaged asset sizes while keeping the basketball gameplay recognizable.

Project Takeaway

This project strengthened my understanding of platform-specific optimization and demonstrated how relatively simple techniques can replace expensive visual features. Rather than removing gameplay feedback entirely, I focused on preserving the experience through smaller assets, texture compression, and lightweight animation alternatives.
